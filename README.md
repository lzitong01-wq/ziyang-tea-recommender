# 紫阳富硒茶个性化推荐

一个纯前端的茶叶推荐小项目：用户填写一份 4 步问卷（年龄、口味、体质、健康需求、饮茶场景、冲泡习惯、饮茶经验），页面根据内置打分算法计算每款茶与用户的匹配度，给出 Top 3 核心推荐和其余茶品的完整排序。

## 功能特点

- **4 步问卷**：基础偏好 → 健康需求 → 场景与冲泡 → 饮茶经验，带必填校验
- **打分推荐**：从口味、健康需求、场景、体质、冲泡、年龄、经验 7 个维度加权计算匹配度（满分 100），口味权重最高
- **三档口味匹配**：区分精确命中 / 近似命中 / 不匹配，而非简单的二元判断
- **体质寒热约束**：偏寒体质喝清热凉茶、偏热体质喝暖胃温茶会被明显降低匹配分，并给出提示
- **推荐理由**：只展示真正匹配到的项，并支持口味/功效/场景的同义词匹配
- **偏好摘要**：结果页顶部展示用户填写的全部信息与备注
- **响应式布局**：适配桌面、平板和手机
- **纯静态**：无需后端和数据库，双击 `index.html` 即可运行，数据保存在浏览器本地存储

## 使用方法

直接用浏览器打开 `index.html`，填写问卷并提交即可看到推荐结果。

```bash
# 如需本地启动一个静态服务器（可选）
python -m http.server 8000
# 然后访问 http://localhost:8000
```

## 推荐算法

纯前端的**规则加权打分模型**（非机器学习）：每款茶按 7 个维度打分求和，满分 100，按总分降序排序，前 3 名为核心推荐。完整逻辑在 `result.html` 的 `calculateScore()` 函数中。

| 维度 | 满分 | 计分规则 |
|------|------|----------|
| 口味偏好 | 25 | 三档：精确命中 25 / 近似命中 15 / 不匹配 5 |
| 健康需求 | 20 | 按命中比例：`命中项数 ÷ 勾选总数 × 20` |
| 饮茶场景 | 15 | 命中 15 / 未命中 7 |
| 体质类型 | 10 | 中性 10；契合体质 10；逆性茶（寒↓凉、热↓温）4；其余 7 |
| 冲泡习惯 | 10 | 命中 10 / 未命中 5 |
| 年龄范围 | 10 | 命中 10 / 未命中 5 |
| 饮茶经验 | 10 | 复杂度适配 10 / 不适配 5 |

**设计要点**：

- **口味权重最高**，因为它是选茶最核心的偏好；健康需求次之。
- **三档口味匹配**：用同义词表区分精确与近似。例如选"醇厚"时，"醇厚,甜润"是精确命中（25），"鲜醇,浓醇"是近似命中（15），"花香,清甜"则不匹配（5）。
- **体质硬约束**：偏寒体质若茶品功效含"清热"（凉性），或偏热体质若茶品含"暖胃/驱寒"（温性），该维度只给 4 分并提示，避免给出伤胃的推荐。
- **同义词归一**：功效（养胃≈暖胃）、场景（休闲放松/下午茶≈休闲品饮、日常待客≈日常饮用）、口味都 built-in 同义词表，避免用户与商品描述用词不一致被误扣分。

**模型性质与局限**：这是固定规则模型，权重由人工设定、未经真实用户数据验证，对所有用户一视同仁，不具备机器学习式的个性化能力。优点是简单、可解释、完全离线可用；调整推荐倾向只需修改 `calculateScore()` 中的分数常量或同义词表。

## 技术实现

- HTML + CSS + 原生 JavaScript，无第三方框架依赖
- 表单数据通过 `localStorage` 在页面间传递
- 用户输入经 HTML 转义后渲染，防止 XSS
- 图片加载失败时回退到本地生成的 SVG 占位图，不依赖外部网络
- 图标使用 Font Awesome CDN；断网时仅图标不显示，不影响核心功能
